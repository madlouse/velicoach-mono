# 任务交接协议

GitHub 的 issue 和 PR 是唯一的交接总线。Claude 定义任务、评审、合并、上线后验证；执行者只交 PR，一律不合并。2026-11-13 定。

## 角色

| 角色 | 做什么 | 怎么开工 |
|---|---|---|
| Claude Duet（产品经理兼评审） | 拆需求、写任务卡、评审 PR、合并进集成分支、上线后验证 | 频道里的会话 |
| Codex 云端 | 按任务卡改代码、跑测试、开 PR | 在 Codex 网页端选仓库发起；在 issue 里 @codex 派任务没有写进官方文档 |
| Codex CLI | 需要本机环境的改动 | 在你的电脑上 `codex` 或 `codex exec` |
| Antigravity | 界面改动和浏览器自测，交截图和录屏 | 在你的电脑上打开应用；读不读 AGENTS.md 要先实测 |
| @codex review | PR 第二意见、安全复查 | 在 PR 下评论 `@codex review` |

## 分工

能写成验收标准、并能用测试或截图判对错的，外派；要判断、要连接器、要不可逆操作的，留给 Claude 和产品负责人。

| 任务类型 | 交给谁 |
|---|---|
| 规格清楚、有测试兜底的编码：修 bug、加接口、重构、补测试 | Codex 云端 |
| 要本地环境才能跑的改动 | Codex CLI |
| 界面改动、要在浏览器里走一遍的流程 | Antigravity |
| 需求、产品取舍、设计决定、架构和 ADR、对外文案 | Claude |
| 要连接器或生产权限的事、执行迁移、上线后验证 | Claude，不可逆的先问产品负责人 |
| 合并 | Claude 评审后合并进集成分支；进 main 或 site 由产品负责人确认 |

外派同时在跑的不超过 3 张；卡住时只上报要人决定的事。

## 任务卡（issue 正文）

```markdown
## 目标
一句话：做完后用户能做到什么。

## 验收标准
- [ ] 每条都能用测试、命令输出或截图判对错

## 验证命令
npm run verify（或本仓库的等价命令）

## 范围
- 可以改：路径
- 不能改：路径、共享契约、迁移、密钥

## 要交的证据
测试输出；界面改动附截图或录屏
```

## 合并前的效果评审（Claude 做）

1. **对验收标准：** 逐条对证据，缺一条就退回。
2. **端到端：** 在预览部署或浏览器里亲自走一遍关键路径，不只看 CI 是否全绿。
3. **对标准：** 设计系统 token 和 design-bar、本仓库的工程规范和不能越过的线、术语和语气。
4. **写结论：** 在 PR 评论里写通过、退回（写清哪条没过）或升级给产品负责人。

## 限制

- Claude Duet 不能直接调用 Codex 或 Antigravity：派活靠 issue，开工要产品负责人在 Codex 网页端或本机点一下。
- Antigravity 只在电脑开着、应用在运行时干活；个人免费，每周有额度上限。
- Codex 云端要 Plus 及以上订阅，本地和云端共用额度；用 GitHub Action 跑 Codex 按 OpenAI API 计费。
