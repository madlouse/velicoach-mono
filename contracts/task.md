# 任务交接协议

GitHub 的 issue 和 PR 是唯一的交接总线。Claude 定义任务、评审、合并、上线后验证；执行者只交 PR，一律不合并。2026-11-13 定。

## 角色

| 角色 | 做什么 | 怎么开工 |
|---|---|---|
| Claude Duet（产品经理兼评审） | 拆需求、写任务卡、评审 PR、合并进集成分支、上线后验证 | 频道里的会话 |
| Codex 云端 | 按任务卡改代码、跑测试、开 PR | 在 Codex 网页端选仓库发起；在 issue 里 @codex 派任务没有写进官方文档 |
| Codex CLI | 需要本机环境的改动 | 在你的电脑上 `codex` 或 `codex exec` |
| Antigravity | 界面改动和浏览器自测，交截图和录屏 | 在你的电脑上打开应用；读不读 AGENTS.md 要先实测 |
| @codex review | PR 第二意见、安全复查 | 在 PR 下评论 `@codex review` |

## 分工

能写成验收标准、并能用测试或截图判对错的，外派；要判断、要连接器、要不可逆操作的，留给 Claude 和产品负责人。

| 任务类型 | 交给谁 | 起步档 |
|---|---|---|
| 机械改动：改名、批量替换、格式、依赖补丁 | Codex 云端 | 轻 |
| 规格清楚、有测试兜底的编码：修 bug、加接口、重构、补测试 | Codex 云端 | 中 |
| 要本地环境才能跑的改动 | Codex CLI | 中 |
| 界面改动、要在浏览器里走一遍的流程 | Antigravity | 中 |
| 跑 E2E、回归（只读，见 [verify/roles.md](../verify/roles.md)） | Claude 的线程或 Antigravity | 轻 |
| 写 E2E 案例、探索找问题 | Claude 的线程 | 中 |
| 需求、产品取舍、设计决定、架构和 ADR、对外文案 | Claude | 重 |
| 要连接器或生产权限的事、执行迁移、上线后验证 | Claude，不可逆的先问产品负责人 | 中 |
| 合并 | 只由主频道评审并合并，含进 main 或 site；产品频道和执行者只开 PR（[工程规范](../standards/engineering.md)「分支和合并」） | 重 |

**选模型：够用的最低配。** 档位不分 CLI：轻是各家最小最快的模型配低 effort，中是主力模型配默认 effort，重是最强的模型配高 effort。从起步档开始；验证没过、而且是能力不够（不是需求不清）才升一档重做；同一类任务连续三次一次通过，下次试低一档。PR 正文写明用的档位和升没升过。新模型出来时，拿最近几张已合并的票在低一档重跑验证，过了就下调起步档。

外派同时在跑的不超过 3 张；卡住时只上报要人决定的事。

## 任务卡（issue 正文）

执行者开工时只看得到产品仓库和这张卡：Codex 云端只克隆一个仓库，读不到私有的本手册。所以写卡的 Claude 把本手册里这次要守的规则原文抄进「上下文」一节（相关的红线、[规范](../standards/)里对应任务类型的条目）；产品仓库里已有的规则和文档只写路径，不抄。

```markdown
## 目标
一句话：做完后用户能做到什么。

## 需求和设计
- 需求：PRD 里的文档路径或需求编号（先改好 PRD 再派活）
- 设计：技术方案或 ADR 的路径；不涉及写「无」

## 验收标准
- [ ] 每条都能用测试、命令输出或截图判对错

## 上下文
- 要守的规则：从本手册抄来的红线和规范条目（原文）；每张卡都抄工程规范「结构和代码」第 6 条（不写注释）
- 先读：产品仓库里的入口文件和相关文档的路径

## 验证命令
npm run verify（或本仓库的等价命令）

## 范围
- 可以改：路径
- 不能改：路径、共享契约、迁移、密钥

## 交付格式
分支名、PR 说明第一行和模板照产品卡「怎么交付」（比如主站的分支前缀和「类别：」一行），写卡时把这几条抄进来

## 要交的证据
测试输出；界面改动附截图或录屏；PR 正文照抄上面的「需求：」一行
```

## 合并前的效果评审（Claude 做）

1. **对验收标准：** 逐条对证据，缺一条就退回。
2. **端到端：** 看集成环境的 E2E 报告：这次改动对应的 PRD 条目都有案例且通过，覆盖率没降（[verify/](../verify/README.md)）；报告还没覆盖的关键路径，自己在预览部署里走一遍。
3. **对标准：** 产品的设计系统 token 和 design-bar、本手册的 [standards/](../standards/) 和产品仓库的不能越过的线、术语和语气。
4. **对文档：** 文档先行和注释检查通过；PRD、技术方案和代码说的一致，对不上的退回（[工程规范](../standards/engineering.md)「文档先行」）。
5. **写结论：** 在 PR 评论里写通过、退回（写清哪条没过），或属于撤不回、花钱、对外发声三类的，升级给产品负责人。

## 限制

- Claude Duet 不能直接调用 Codex 或 Antigravity：派活靠 issue，开工要产品负责人在 Codex 网页端或本机点一下。
- Antigravity 只在电脑开着、应用在运行时干活；个人免费，每周有额度上限。
- Codex 云端要 Plus 及以上订阅，本地和云端共用额度；用 GitHub Action 跑 Codex 按 OpenAI API 计费。

出处：OpenAI Codex 文档（GitHub 集成、云端任务、AGENTS.md）、Google Antigravity 文档与定价页，2026-11-13 读取。
