# 运行时覆盖率

E2E 的能力模块之一：给集成环境的构建插桩，E2E 跑完后统计源码有多少被真实用户路径走到，像 Java 的 JaCoCo 一样。它回答「案例覆盖了 PRD 之后，代码里还有多少没被用户路径碰过」。

## 怎么测

| 部分 | 做法 |
|---|---|
| 浏览器里的代码 | 构建时插桩（istanbul，比如 vite-plugin-istanbul、babel-plugin-istanbul），跑完从页面取覆盖数据；或用 Playwright 读 V8 覆盖率再换算到源码 |
| 服务端代码 | Node 进程开 `NODE_V8_COVERAGE`，用 c8 出报告；Serverless 函数在集成环境用插桩构建 |
| 数据库函数 | pgTAP 和权限矩阵另算，不混进这个数字 |
| App | Android 用 JaCoCo，iOS 用 Xcode 的代码覆盖率 |

各部分合并成一份报告（行、分支、函数），按源码目录或 PRD 模块分组。

## 要守住的结果

- **只在集成环境插桩：** 线上和要发布的构建不插桩；插桩构建和发布构建出自同一个提交。
- **每次都出报告：** 报告和运行编号、提交号放在一起，PR 或发布记录里附摘要。
- **门槛只升不降：** 先跑一次定基线，门槛写进产品的配置；之后低于基线就失败，要降必须在 PR 里说明并由产品负责人确认。Veli 设备矩阵的 `baseline.json` 只许变好，是同样的做法。
- **看没走到的代码：** 报告里没被走到的分支，要么补一条对应 PRD 的案例，要么说明它是谁的代码路径（死代码就删，内部任务就交给单元测试），不为了凑数写不对应需求的案例。
- **和单元测试分开报：** E2E 覆盖率和单元、集成测试的覆盖率各报各的，不相加。

第一次接入时先报数，不拦合并；有了基线再加门槛。
