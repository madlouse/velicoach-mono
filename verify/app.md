# App 验收

E2E 的能力模块之一：在手机上验收安装后的 PWA 和以后的原生 App。Veli 的原生 App 在 B2；在那之前这里管 PWA 在真机和模拟器上的表现。

## 和 Web 不同的地方

| | Web | App |
|---|---|---|
| 入口 | 网址 | 主屏图标、通知、小组件、分享和深链 |
| 系统能力 | 浏览器给的 | 通知、健康数据、相机、后台刷新、离线 |
| 环境 | 浏览器配置文件 | 设备或模拟器、安装包、系统权限、系统版本 |
| 驱动 | 浏览器自动化 | PWA 用移动端浏览器自动化；原生用平台的界面测试（iOS 的 XCUITest，Android 的 Espresso 或 UI Automator），或 Maestro、Appium 这类跨平台工具 |
| 覆盖率 | 浏览器和服务端插桩 | Android 用 JaCoCo，iOS 用 Xcode 的代码覆盖率，PWA 同 Web |

## 要守住的结果

- **从用户的入口进：** 案例从通知、小组件、深链进来时，就真的从那里进，不直接打开内部页面。
- **系统弹窗和权限：** 授权、拒绝、之后再撤回三种情况都有案例；准备步骤负责把权限置到案例要的状态。
- **离线和中断：** 断网、切到后台、被系统杀掉后回来，数据和状态不丢；这一类和 [explore.md](explore.md) 的中断探测共用。
- **真机抽查：** 模拟器跑全量，上线前在至少一台 iPhone 和一台 Android 真机上跑关键路径；真机做不了自动化的，在报告里写明手工走过的路径和截图。
- **安装包可追溯：** 报告写明安装包的版本和提交号；验的包就是要发的包。

PWA 阶段沿用 [web.md](web.md) 的驱动，加上安装到主屏、离线、推送三类案例。原生 App 开工时再选驱动工具，写进产品仓库的 ADR，案例不用改。
